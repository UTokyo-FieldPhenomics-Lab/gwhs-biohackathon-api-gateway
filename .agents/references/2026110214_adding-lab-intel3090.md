# Adding `lab-intel3090` to the pool

2026-11-02. A Windows 11 workstation with an RTX 3090 joined the pool as a fourth backend for all
three models. Address and login are in `.agents/local/pool.md`; this note is what was done, what
broke, and what the next machine should do differently.

## The path was shorter than the design says

`lab-3090` reached the new machine **directly over the wired campus network**, never through
`gwhs-host` and never over the tailnet: `ip route get` answered via the room gateway and TCP 22
connected. So the rule in `backend-pool.md` — "every administrative connection goes through the
gateway host" — is how the contract is written, not a property of the routes. What settled the SSH
bootstrap was that fact: the operator had a shell on both ends (RustDesk), so the key went in at the
machine's own console and no password login was ever used.

The participant path is still the tailnet one: from `gwhs-host`, `ip route get` answered
`dev tailscale0 table 52 src <the host's tailnet address>`, and `/health` answered `200` down it.

## What was run

- **SSH**: `winget install --id Microsoft.OpenSSH.Preview`, service automatic, and the caller's
  public key written by hand into `%ProgramData%\ssh\administrators_authorized_keys` with `ascii`
  encoding and the `icacls` reset. `whoami` answered `rtx3090intel\crest`; the login is `crest`.
  Key authentication worked on the first attempt, `BatchMode=yes` included.
- **Images**: `git archive` per model, `scp` to the machine, extracted inside WSL, then
  `DOCKER_CONFIG=/tmp/dcfg docker build` in the same order as the doc. Build times: `sam3.1-meta`
  15 min (3.5 GB of weights), `gwfss-segformer-b4` 3.8 min, `tasselnetv4` 3.9 min.
- **Containers**: the run line from the doc, one per model, `-p 12711`/`12712`/`12713` to `12711`,
  the host's `BIOHACK_BACKEND_TOKEN`, and `SAM31_MACHINE` / `GWFSS_MACHINE` / `TNV4_MACHINE` set to
  `lab-intel3090`. `/health` was `200` within 15 s (sam3.1) and immediately for the other two.
- **Pool**: the three URLs appended to `models.json` on `gwhs-host` (backup written beside it),
  gateway restarted. `GET /models` then read `backends_up` 4/3/3 and `GET /pool` listed
  `lab-intel3090` alive on all three at rtt 0.58 s.

## What broke, and why it will happen again

- **`Add-WindowsCapability … OpenSSH.Server` sat at 100 % and never returned.** The capability's
  payload comes from Windows Update, and on a managed machine the DISM provider waits there. The
  winget MSI is the same binary without that hop; the package id is `Microsoft.OpenSSH.Preview` —
  the documented `Microsoft.OpenSSH.Beta` no longer resolves.
- **`Set-Content -Encoding ascii` failed with "Unable to match the identifier name ascii".** A stray
  control character rode along with the pasted key (`^B` at the end of the line). Re-running the
  line cleanly worked; nothing about the encoding was wrong.
- **The `tasselnetv4` archive had no `--prefix`**, so `python3 -m zipfile -e … .` in the home
  directory sprayed `Dockerfile`, `vendor/`, `tests/` and the rest beside the real files, and
  `docker build … tasselnetv4` failed with `path "tasselnetv4" not found`. The fix was to rebuild
  the archive with `--prefix=tasselnetv4/`, extract into place, and delete the strays only after
  `diff -rq` proved each was byte-identical to the archive's copy.
- **Quoting PowerShell through `cmd` from `ssh` is a dead end.** Two attempts at `Get-PSDrive` and
  `Get-ItemProperty` mangled the path and the hashtable. Piping a bash script to `wsl -e bash -s`
  worked first time and is what the remaining steps used.
- **`backends_up` read 3 on two models after the deploy.** Two entries in `models.json` were already
  dead before this machine existed (`refused`, `failures: 8`), so 4 entries and 3 alive is correct;
  the new backend was in the alive set on all three.

## What to carry forward

1. **A machine that is administered by an agent should be bootstrapped at its own console.** The
   password login in `gpu-backends-local.md` is for the reader who has no console; when there is
   one, the key is four lines pasted into PowerShell and the SSH channel is up in a minute.
2. **Check the archive's prefix before extracting into a home directory.** `git archive` with
   `--prefix` is what makes the context a directory; without it the build context is the home.
3. **Allow rules are a union.** The machine ended with two inbound rules for 22 — the installer's
   and a narrower one made by hand — so the narrow one restricted nothing. The pool now accepts the
   intranet as the boundary and leaves the installer's rule alone.
