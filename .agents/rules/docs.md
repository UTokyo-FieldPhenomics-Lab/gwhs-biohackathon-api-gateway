# Docs Rules

Package: `docs/`. Repo-wide invariants are in [`project.md`](project.md) and are not repeated here.

- **Disposable by design.** The site exists for the event window and may be deleted whole afterwards,
  so no production pipeline may depend on it. Retiring it means removing the `docs` DNS record as
  well, or the name stays claimable by someone else.
- **Hosted by GitHub Pages at `docs.global-wheat.com`.** `zensical.toml` at the repository root builds
  `docs/content/` into `site/`, and `.github/workflows/docs.yml` publishes that artifact from `main`
  with `--strict`; nothing in the build holds a secret, and no host of ours is involved. The hand
  steps behind the domain are `deploy/README.md` §6.
- **The content root holds site material only.** `docs_dir` is `docs/content/`, never `docs/`, because
  a virtualenv anywhere under the content root stops the build emitting `site/assets/` entirely: the
  pages publish unstyled and the build reports no problem. The subproject's `pyproject.toml`,
  `uv.lock`, and `.venv` therefore sit outside it.
- **Every published page is written for a participant.** The site answers what the API offers, how to
  call it, what comes back, and what the examples are. Internal material — index fields and tables,
  the object-key layout, upstream provenance, and the development sample — stays outside
  `docs/content/`, which is why `data-layout.md` sits beside the subproject rather than inside it.
- **Locked like the rest.** `docs/` commits a `uv.lock` like every other subproject:
  `requires-python` is a floor and the lock pins the rest. Re-run `uv lock` whenever `pyproject.toml`
  changes.
- **Markdown is the source of truth, including for the notebook.** `docs/content/examples/notebook.md`
  is the only place the walkthrough is written; `quickstart.ipynb` beside it is generated by
  `docs/scripts/make_notebook.py`, committed because Colab can only open a notebook that sits at a
  GitHub path, and regenerated before every build. `git diff --exit-code` on it in the workflow is what
  stops the committed copy from describing a page that has moved on. No output is committed with a
  snippet.
- **The notebook page is written to be convertible.** Only `python` and `bash` fences, no language
  tabs (a notebook has one kernel), no admonitions (Jupyter renders `!!!` literally), relative image
  paths, and `<!-- notebook: skip -->` around anything that is the page's chrome. The converter refuses
  the rest by name rather than shipping a notebook with a hole in it, so a page that breaks these
  fails the build instead of quietly losing a section.
- **The reference is the API's own page, framed.** Zensical has no OpenAPI plugin and needs none:
  FastAPI serves `/docs` and `/openapi.json` at runtime, and `docs/content/api/reference.md` frames
  that page so a reader stays inside the site. There is no generated markdown copy of the reference, in
  `docs/content/api/` or anywhere else — a second rendering of the same contract would be a second
  thing to keep true.
- **The gateway owns the served reference, `docs/` never imports the app.** The page the site frames
  is registered by the application, which is what lets it carry the frame's height reporter and the
  dark palette; see [`gateway.md`](gateway.md). The site itself has no Python dependency on the
  gateway and builds from markdown alone.
- **Policy prose is handwritten.** The refusals, the key, and the limits are written by hand on
  `api/http.md` — status codes and their meaning are not in the OpenAPI document, so nothing can
  generate them, and they are the sentences a participant needs when a call fails.
- **A snippet ships only after it has been run.** The site's snippets were executed against real rows
  before publication — the palette split in three languages, the RLE decoder against an object whose
  `area` it has to equal — and the numbers they print are the printed numbers. The build does not
  execute them: it has no NumPy and no token, so a page that needs either is verified by hand.
- **Figures are generated, not drawn.** `docs/scripts/make_figures.py` builds every image the pages
  show from published rows and one recorded geometry fixture, so a figure can be regenerated when the
  data changes. It lives outside `docs/content/`, and it needs `--with pillow --with numpy` because
  the site's own environment carries neither.
- **One frame script serves both frames, and it lives in `docs/content/api/`.** The reference page is a
  frame inside `api/reference.md`, and the run-a-model page is a frame inside `examples/demo.md`;
  `docs/content/api/frame.js` sizes each one and passes the reader's palette into it. A frame is
  matched by the `data-api-frame` attribute rather than by the id of the box it sits in, so one file
  sizes every frame the site shows, and a new one needs no change here.
- **A page explains the API, not the site.** Sentences about how this site is built — why a table is
  handwritten, why a figure is generated, what a `curl` on a page proves — are `.agents/` material.
  Every published sentence has to be one a participant needs.
- **One decoder, and it is the client's.** RLE and palette decoding live in `clients/` — one
  implementation per language, checked there — and the Clients page hands them to a participant as
  files to download. The live demo page and the API's run-a-model page load
  `clients/global-wheat.js` from this site rather than carrying a copy, so a demo and a tutorial
  cannot disagree about what a correct decode is. Anything on a page that can fail to load — a
  decoder, a recorded example — says so in words where the reader is looking, because a blank canvas
  reads as a result.
- **The client files are copies in the build output, never in the source tree.** They are the
  documented download URLs, so they have to be served from this origin — a raw GitHub URL is
  `text/plain` and a browser refuses it as a module — but their one source is `clients/`.
  `docs/scripts/sync_clients.py` copies them into `site/clients/` **after** the build and before the
  upload, and it refuses to run before one, because a build overwrites `site/`. Nothing appears under
  `docs/content/clients/` except the page and its figures: a copy of a source file in the source tree
  is a copy somebody edits by mistake. The cost is a local preview that lacks the downloads — check
  them with `uv run --project docs zensical build --strict && python3
  docs/scripts/sync_clients.py && python3 -m http.server --directory site`.
- **English only**, consistent with the rest of the repository.
